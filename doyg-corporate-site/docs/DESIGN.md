## ① サイトコンセプト

### コンセプトステートメント

> # 地平をひらく。
> ### Open the Horizon — 熊本から、次の価値を。

### なぜこのコンセプトか

このグループの本質は「一貫性のなさ」ではなく **「一つの土地の上に、多様な営みが重なっていること」** です。
携帯ショップ、クルマ、ゴルフ場、介護、飲食、不動産——業種はバラバラに見えますが、共通項は明確です。

- すべてが **熊本という一つの土地** の上にある
- すべてが **人の生活のインフラ** である
- すべてが **「業種の枠組みを超えた価値創造企業への変革」** という一本の線で結ばれている

そこで、サイト全体を貫くメタファーを **「地平線（Horizon）」** に設定します。
阿蘇のカルデラ、有明の海、熊本平野。熊本は「地平が見える土地」です。
そして地平線は、**「そこまでが今の領域」と「その先へ行く」の両方を同時に意味する線** です。
地域密着（この土地に根を張る）と挑戦（枠を超える）という、一見矛盾する2つのブランドキーワードを、
1本の線で同時に表現できる——これがコンセプトの中核です。

### サイトが果たす役割（優先順位）

| 優先 | 役割 | 主ターゲット | サイト上の担保 |
|---|---|---|---|
| 1 | **採用強化** | 学生・求職者 | 全ページからRECRUIT導線／TOPに専用CTAセクション／人と土地の写真を主役に |
| 2 | **企業ブランド向上** | 全員 | 余白と写真の質、コピーの品格、スクロール体験 |
| 3 | **グループの一体感** | 取引先・投資家 | 4事業を「並列カード」ではなく「一つの地平の上の連なり」として表現 |
| 4 | **企業価値の向上** | 投資家・取引先 | 数字セクション／2030長期目標／中期経営計画の可視化 |
| 5 | **地域への信頼感** | 地域住民 | サステナビリティを「飾り」でなく主要セクションとして厚く扱う |

### 3つの設計原則

1. **写真が語り、文字は補う。**
   説明文を減らし、写真を大きく使う。文章は「読ませる」のではなく「刺さる一行」を置く。
2. **カードを使わない勇気。**
   4事業もニュースもカードで並べない。カードグリッドこそがテンプレート感の正体。
   代わりに **全幅の帯（Band）** と **罫線のリスト（Rule List）** で構成する。
3. **1画面に1メッセージ。**
   スクロールごとに「今、何を伝えられたか」が1つに絞られている状態を保つ。

### やらないこと（禁止事項の明文化）

- ❌ 3カラムのアイコン付きカードグリッド
- ❌ 背景に敷いた斜めの図形・グラデーションの飾り
- ❌ 影の強いカード（`box-shadow` は最小限、`0 1px 2px` 程度まで）
- ❌ 派手なガラスモーフィズム（ヘッダーの背景に極薄く使うのみ）
- ❌ 中央揃えの短文の連続（左揃え基調で紙面に軸を通す）
- ❌ アニメーションの多重掛け（1要素1アニメーション）
- ❌ Bootstrap的なボタン（角丸999pxの塗りボタンを主役にしない）

## ② デザインコンセプト

### キービジュアル思想：「1本の地平線と、大きな余白」

サイト全体に **`--rule` という1pxのヘアライン** を通し続けます。
セクション区切り、リスト区切り、テキストの下線、すべてが同じ太さ・同じ色。
装飾を「線1本」に集約することで、写真と余白だけが残る紙面をつくります。

### 版面設計（グリッド）

```
PC（1440px想定）
┌──────────────────────────────────────────────────────────────┐
│ ← 120px →│                1200px content               │← 120px →│
│          │  12 column / gutter 32px                    │         │
└──────────────────────────────────────────────────────────────┘
最大コンテンツ幅：1200px（テキスト主体）／1400px（写真主体・ワイド）
フルブリード：100vw（Hero・事業帯・Sustainability・Recruit CTA）
```

- **本文の1行あたり文字数**：日本語 32〜42文字（`max-width: 34em`）に制限。読みやすさの生命線。
- **セクション間の縦余白**：PC `clamp(120px, 12vw, 200px)` ／ SP `80px`
  → 一般的な企業サイトの約2倍。これが「余白を大胆に」の実体です。

### 「大胆な余白」の定義（数値で握る）

| 箇所 | PC | Tablet | SP |
|---|---|---|---|
| セクション上下padding | 160〜200px | 120px | 80px |
| 見出し → 本文 | 40px | 32px | 24px |
| 本文 → CTA | 64px | 48px | 40px |
| 画面左右マージン | 120px | 64px | 24px |
| 大見出しの上の空白 | 見出し高さの1.5倍以上 | - | - |

### 写真の扱い

- Hero と各事業帯は **フルブリード**（左右余白ゼロ）
- 写真の上に文字を乗せる場合は、**単色オーバーレイではなくグラデーションマスク**（下から navy 60% → 透明）
- 写真の角丸は **0px**（フルブリード時）／ **12px**（コンテンツ内配置時）
- アスペクト比は **16:9 / 3:2 / 4:5（縦位置）** の3種のみに統一。バラバラの比率を混ぜない。

### トーン&マナー参照

| 参照 | 何を採るか |
|---|---|
| Apple | 1画面1メッセージのスクロール構成、写真の主役化 |
| SONY | 黒に近い濃色と白のコントラスト、タイポの緊張感 |
| TOYOTA | 数字とファクトの見せ方、グローバル企業としての整列感 |
| Panasonic | 情報量の多い下層ページでも崩れない秩序 |
| MUJI | 余白そのものを情報として扱う姿勢、装飾の排除 |

**ただし丸パクリはしません。** 上記に対する差分＝「熊本の自然色（Navy / Water Blue / Aso Green）」と「地平線モチーフ」がこのサイトの固有性です。

### URL設計ルール

- 全ページ **ディレクトリ型 + 末尾スラッシュ**（`/about/`）
- 英小文字・ハイフン区切りのみ。日本語URL・全角URLは使わない（現行サイトの `/ｃｏｍｐａｎｙ/` のような全角URLは廃止）
- ニュースは `/news/{YYYYMMDD}-{slug}/` を推奨（CMS移行時の互換性を担保）

### グローバルナビゲーション

```
[LOGO]        ABOUT   BUSINESS   GROUP   SUSTAINABILITY   NEWS      [ RECRUIT ]  [☰]
```

- 主要5項目のみ露出。MESSAGE は ABOUT 配下、CONTACT はフッターとドロワー内。
- **RECRUIT のみ視覚的に独立**（枠線ボタン）。採用強化という最優先目的をナビで表明する。
- `☰` はPCでも表示。開くと全ページを俯瞰できる **フルスクリーンメニュー**（下層への到達を1クリックに）。

### ページ内の情報の優先順位（採用ターゲット最適化）

学生・求職者は「何をしている会社か」を **5秒** で判断します。
そのため TOP のスクロール順を **理念 → 事業 → 規模 → 社会性 → 採用** とし、
「規模（数字）」を中盤に置いて **"ちゃんとした会社だ"** を早い段階で担保します。

### パンくずリスト

全下層ページに設置（`BreadcrumbList` の構造化データ付き）。TOPには置かない。

```
HOME > BUSINESS > カーライフ事業
```

**接頭辞ルール**

| 接頭辞 | 意味 | 例 |
|---|---|---|
| `l-` | Layout（配置） | `.l-container` `.l-header` |
| `c-` | Component（再利用可能・汎用） | `.c-button` `.c-news-item` |
| `p-` | Project（ページ固有） | `.p-hero` `.p-mission` |
| `u-` | Utility（単一責務） | `.u-visually-hidden` |
| `js-` | JS用フック（**CSSでは絶対に使わない**） | `.js-reveal` `.js-parallax` |
| `is-` / `has-` | 状態 | `.is-active` `.is-scrolled` |

**その他ルール**

- **詳細度は常に0-1-0（クラス1つ）を目標。** ネストは最大2段まで。IDセレクタ禁止。`!important` 禁止（`u-` レイヤーのみ許容）。
- 色・余白・フォントサイズの **生の値をコンポーネントに直書きしない**。必ず CSS 変数を経由。
- ファイル冒頭に「このファイルが何を担当するか」のコメントブロックを必ず置く。

### JavaScript 設計方針

- **ES6 モジュール**（`<script type="module">`）。`var` 禁止、`const` 優先・再代入時のみ `let`。
- jQuery 不使用。外部ライブラリ **ゼロ** で完結させる。
- 各モジュールは `export function initXxx() {}` の形で、`main.js` が初期化を集約。
- 対象要素が存在しなければ即 `return`（全ページで同じ `main.js` を読んでもエラーにしない）。
- スクロール連動は **すべて IntersectionObserver**。`scroll` イベントの直接リスニングは
  パララックスとヘッダーのみに限定し、`requestAnimationFrame` でスロットルする。
- `prefers-reduced-motion: reduce` を JS 側でも検知し、アニメーションを実行せず最終状態を即適用。

// main.js の構造イメージ

import { initHeader }       from './modules/header.js';
// …

const boot = () => {
  initHeader();
  initScrollReveal();
  // …
};

document.readyState === 'loading'
  ? document.addEventListener('DOMContentLoaded', boot, { once: true })
  : boot();

## ⑥ 画像の使用指示

### 撮影・選定の全体方針

**「熊本の光」で撮る。** 全カットを通して以下を統一します。

- **時間帯**：朝〜午前の斜光、または夕暮れのマジックアワー。真昼の硬い光は避ける。
- **彩度**：やや低め（-10〜-15）。緑と青を残し、赤みを抑える。

### 書き出し仕様（パフォーマンス最優先）

- **フォーマット**：`AVIF` → `WebP` → `JPEG` の順に `<picture>` でフォールバック
- **容量上限**：Hero 400KB / 全幅写真 250KB / コンテンツ内写真 150KB / サムネイル 60KB
- **解像度セット**：`1x` と `2x`（`srcset` の `w` 記述子で `640 / 1024 / 1600 / 2400` の4段）
- **属性**：`width` / `height` を必ず明記（CLS 対策）、Hero 以外は `loading="lazy"` `decoding="async"`
- **Hero のみ** `fetchpriority="high"` + `<link rel="preload">`
- **alt テキスト**：装飾画像は `alt=""`。内容を持つ画像は「何が写っているか」を具体的に書く（アクセシビリティ AA 要件）

### 動画の実装仕様

```
<video> 属性：autoplay muted playsinline loop preload="metadata" poster="..."
- 音声トラックは含めない（ファイルサイズ削減 + iOS 自動再生の確実性）
- PC: hero.webm (VP9, ~3MB) → hero.mp4 (H.264, ~5MB)
- SP: 480px 未満は動画を読み込まず poster 画像のみ表示（通信量配慮）
- prefers-reduced-motion: reduce → 動画を再生せず poster 固定
- Save-Data ヘッダー / navigator.connection.saveData → 動画スキップ
```

## ⑦ 使用アイコン

### 方針

**アイコンフォント（Font Awesome 等）は使用しません。** 全て **インラインSVG + SVGスプライト** で実装します。

理由：①不要な文字コードの読み込みを避ける ②`currentColor` で色を継承できる ③スクリーンリーダーに誤読されない ④線幅を統一できる

### デザイン規格

| 項目 | 値 |
|---|---|
| グリッド | 24 × 24 px |
| 線幅 | 1.5px（`stroke-width: 1.5`） |
| 線端 | `stroke-linecap: round` / `stroke-linejoin: round` |
| 塗り | なし（`fill: none`）。線のみで構成 |

### 行間・字間（和文の可読性設計）

| 用途 | line-height | letter-spacing | 備考 |
|---|---|---|---|
| Display（Hero） | **1.25** | **-0.02em** | 大きい文字ほど詰める |
| H1 / H2 | **1.4** | **-0.01em** | |
| H3 / H4 | **1.5** | **0** | |
| リード文 | **1.9** | **0.02em** | 呼吸を持たせる |
| **本文** | **1.9** | **0.04em** | ★和文はこれくらい空けないと上質に見えない |
| 補足・キャプション | 1.8 | 0.04em | |
| 英字ラベル | 1.4 | **0.16em** | ★英小見出しは大きく空ける（`text-transform: uppercase`） |
| 数字（Stat） | 1.0 | -0.03em | `font-variant-numeric: tabular-nums` |

**和文タイポグラフィの要点**
- 本文の `line-height: 1.9` と `letter-spacing: 0.04em` が「上質さ」の8割を決めます。詰まった行間は即座に安っぽく見えます。
- 1行あたり **32〜42文字**（`max-width: 34em`）を厳守。
- 見出しの改行は `<br>` に頼らず、`word-break: auto-phrase`（対応ブラウザ）＋ 手動 `<wbr>` で自然な文節改行に。
- 数字と英字は必ず Inter に切り替える（`--font-num`）。和文フォントの数字は幅が不揃いで安く見えます。
- 禁則処理：`line-break: strict;` `overflow-wrap: anywhere;`

### 見出しの構造パターン（全セクション共通）

```
01 — BUSINESS          ← --fs-label / Inter / 0.16em / --color-text-muted
4つの事業領域           ← --fs-h2 / Noto Sans JP 700 / --color-text-strong
─────────────          ← 1px ヘアライン（--color-rule）
```

この3層構造をすべてのセクションで反復することが、サイト全体の統一感をつくります。

### 見出しレベルの意味論（アクセシビリティ）

- 各ページ `<h1>` は1つのみ。TOP の `<h1>` は「ドゥ.ヨネザワ企業グループ」（Hero のキャッチコピーは `<p>` として `--fs-display` を当てる、あるいは `<h1>` にキャッチを入れロゴを `<p>`）→ **Phase1 で最終確定**。
- 見出しレベルを飛ばさない（h2 の次に h4 を置かない）。
- 見た目の大きさと見出しレベルは分離する（クラスで制御）。

## ⑩ アニメーション設計

### 基本原則

1. **1要素につき1アニメーション。** フェード＋スケール＋回転の同時掛けは禁止。
2. **動きは「入り」のみ。** 画面外に出る際のアニメーションは付けない（スクロールバックで再生し直さない）。
3. **速すぎず、遅すぎず。** 主要モーションは **700〜900ms**。企業サイトで300msは軽薄に、1500msは重く感じます。
4. **イージングは1種類に統一。** `cubic-bezier(0.16, 1, 0.3, 1)`（ease-out-expo系）を全体で使用。「スッと出て、静かに止まる」品のある動き。
5. **`prefers-reduced-motion: reduce` で全て無効化。** これは AA の必須要件です。

```css
:root {
  --ease:         cubic-bezier(0.16, 1, 0.3, 1);  /* 主モーション */
  --ease-inout:   cubic-bezier(0.65, 0, 0.35, 1); /* 状態変化 */
  --dur-fast:     200ms;
  --dur-base:     400ms;
  --dur-slow:     800ms;
  --dur-slower:   1200ms;
  --reveal-y:     24px;    /* フェードアップの移動量 */
  --stagger:      80ms;    /* 連続要素の遅延間隔 */
}
```

### 「気持ちいいスクロール体験」をつくる仕掛け

1. **スクロールジャックはしない。** ネイティブのスクロールを奪うと、必ずどこかで気持ち悪くなります。速度は常にユーザーのもの。
2. **`scroll-behavior: smooth`** はアンカーリンクのみ（`html` 全体には付けない）。
3. **リズムを設計する。** セクションの高さを「100vh → 60vh → 80vh × 4 → 70vh → 90vh → auto → 100vh」と意図的に変化させ、単調さを消す。
4. **パララックスは控えめに（±12%まで）。** 大きく動かすと酔います。写真が「その場に留まろうとしている」程度が上品。
5. **`content-visibility: auto`** を各セクションに付与し、画面外の描画コストを削減 → スクロールのカクつきをゼロに。

### IntersectionObserver 実装方針

```js
// scroll-reveal.js の設計イメージ
const OPTIONS = {
  root: null,
  rootMargin: '0px 0px -12% 0px',  // 少し早めに発火させず、確実に見えてから出す
  threshold: 0.15,
};

// - 発火後は unobserve して再生を1回に限定（スクロールバックでちらつかせない）
// - stagger は要素の index から CSS カスタムプロパティ --i を渡し、CSS側で
//   transition-delay: calc(var(--i) * var(--stagger)) として計算する（JSでsetTimeoutしない）
// - IntersectionObserver 非対応環境では即座に .is-revealed を全付与（コンテンツは必ず見える）
```

**重要な設計判断**：`.js-reveal` の初期状態（`opacity: 0`）は **JavaScript が動作した後にのみ適用** します。
`html.js-enabled` クラスを `<head>` 内のインラインスクリプトで付与し、`.js-enabled .js-reveal { opacity: 0 }` とすることで、
**JS が失敗しても内容が真っ白にならない** ことを保証します。これは可用性とアクセシビリティの両面で必須です。

### モーション削減対応

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
  /* 要素は「最終状態」で即表示する（消えたままにしない） */
  .js-reveal { opacity: 1 !important; transform: none !important; }
  .js-parallax { transform: none !important; }
}
```

JS側でも `window.matchMedia('(prefers-reduced-motion: reduce)')` を監視し、
パララックスとカウントアップの計算処理自体を実行しません（CPU負荷も削減）。

## ご確認・ご判断をお願いしたい点

実装前に以下をご判断ください。**②以外は実装と並行して確定でも進行可能** です。

### ① キャッチコピーの決定（要選択）

| 案 | コピー | 狙い |
|---|---|---|
| **A（推奨）** | **地平を、ひらく。**<br>熊本から、次の価値を。 | 地域密着と挑戦を1語で両立。コンセプトと完全に一致。抽象度が高く多事業を包含できる |
| B | この土地と、生きる。<br>この土地を、変える。 | 対句で力強い。地域住民・採用に響く。やや情緒寄り |
| C | 業種の、その先へ。 | 「業種の枠組みを超えた価値創造企業への変革」という長期目標に直結。投資家・取引先向けに明快 |

### ② 掲載データの確定（要確認）

従業員数・売上高・法人数・資本金・沿革・グループ会社の正式名称一覧。公開情報ベースの数値を仮置きしているため、正式値の支給をお願いします。

### ③ 写真・動画素材の調達方針（要判断）

- **A案**：新規撮影（推奨。ブランドサイトの質は写真で決まります）
- **B案**：既存素材の再編集
- **C案**：Phase1〜3 は高品質ストックフォトで仮組みし、後日差し替え（**進行を止めないため、まずはC案で実装 → 撮影後に差し替え** を提案します）

### ④ CMS 化の要否

NEWS の更新頻度が高い場合、静的HTMLでは運用負荷がかかります。将来 WordPress 化する想定があれば、
Phase1 の時点で **テンプレート分割を意識したHTML構造**（ループ部分の明確化）にしておきます。
※ 本リポジトリに SWELL 関連の実装があるため、WordPress 運用の可能性を想定しています。

### ⑤ 多言語対応の要否

英語版の予定があれば、Phase1 から `lang` 属性・`hreflang`・ディレクトリ設計（`/en/`）を織り込みます。
