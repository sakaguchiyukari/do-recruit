# ホームページ セキュリティ点検チェックリスト

複数のWordPressサイト・静的HTMLサイトを、サイトごとに定期セキュリティ点検するための1ページのツール。

## 2つの使い方（保存先は開き方で自動的に切り替わる）

| 開き方 | 保存先 | 共有 |
|---|---|---|
| claude.ai の Artifact（チーム共有版） | Artifact の共有データベース | ログインしたチームメンバー全員で、リアルタイムに共有 |
| `index.html` をブラウザで直接開く（ローカル版） | そのブラウザの localStorage | 共有されない |

### チーム共有版の公開・更新

1. `node tools/build-artifact.mjs` で `dist/artifact.html`（CSS・JSを埋め込んだ1ファイル版）を生成する。
2. Claude Code から `dist/artifact.html` を Artifact として公開する。capabilities は
   `{"db": {}, "user": {"scopes": ["profile"]}, "downloads": true}`。
3. claude.ai でページを開き、右上の共有メニューから組織（またはメンバー）に共有する。
   **点検結果を書き込む人には「閲覧のみ」ではなく編集できる権限を付ける**（閲覧のみの人は見るだけになる）。

- 共有データは `sites` コレクションに、サイトごとに1ドキュメントで保存する。
  項目の更新はその項目だけをマージするので、同じサイトの別の項目を同時に編集しても上書きし合わない。
- 最終更新者はユーザーID（`updatedBy`）だけを保存し、名前は表示のたびに取得する。
- Artifact 内では `confirm()`・印刷・`<a download>` が使えないため、確認はページ内ダイアログ、
  書き出しは downloads capability を使い、印刷ボタンは表示しない。
- `dist/artifact.html` は生成物なので直接編集しない。

## 構成

```
security-checklist/
├─ index.html              … 本体（サイト一覧 / サイト情報 / チェックリスト2種 / 診断の進め方）
├─ assets/css/style.css    … CSS（1ファイル / FLOCSS + BEM / :root でトークン管理）
├─ assets/js/main.js       … サイト管理・確認状況・保存・書き出し/読み込み・フェードイン（defer の単一ファイル）
└─ assets/img/             … 画像（仮名称。未配置）
   ├─ favicon.ico
   ├─ apple-touch-icon.png
   └─ ogp/ogp-security-checklist.png（1200×630）
```

- `index.html` をブラウザで直接開いても動く（ESモジュールを使っていないため）。
- パスはサブディレクトリに置く前提で相対パスにしている。

## 機能

| 機能 | 内容 |
|---|---|
| 複数サイト管理 | サイトの追加・切替・削除。サイトごとに種類（WordPress / 静的HTML）、点検日、担当者、点検結果を保存 |
| 確認状況 | 各項目を「OK / 確認中 / 要検討 / 対象外」から選ぶ。選択中のボタンをもう一度押すと未確認に戻る |
| メモ | 確認中・要検討を選ぶとメモ欄が開く（入力済みのメモは常に表示） |
| 集計・絞り込み | 状況ごとの件数を表示。未確認・確認中・要検討だけを表示できる |
| 進捗 | 「完了」＝ OK ＋ 対象外 |
| 書き出し / 読み込み | 全サイトのデータをJSONで書き出し・読み込み（PCの移行・バックアップ用。読み込むと現在の記録は置き換わる） |
| 印刷 | 選択中サイトの結果を印刷・PDF保存（ローカル版のみ。選んだ状況と入力済みのメモのみ出力） |
| 最終更新者 | 共有版では、サイトごとに最後に更新した人の名前を表示 |

## 項目の追加・変更

1. `index.html` の該当カテゴリ（`<section class="p-category">`）にある `<li class="c-check js-item">` を1つ複製する。
2. `data-item`、ラジオボタンの `name` / `id`、`label` の `for`、メモの `id` / `name` を、ほかと重ならない値にそろえる（例：`wp-core-09`）。
   この値が保存データのキーになるため、**既存の値は変更しない**（変更すると保存済みの結果が表示されなくなる）。
   値の形式は `種類-カテゴリ-2桁の番号`（例：`html-server-07`）にする。それ以外の形式は読み込み時に無視される。
3. 件数・進捗・集計は JS が HTML から数えるため、数字を直す必要はない。
4. 共有版にも反映するときは、`node tools/build-artifact.mjs` で再生成して公開し直す（共有データは消えない）。

WordPress・静的HTMLで共通のカテゴリ（サーバー / ドメイン・DNS / SSL・通信 / バックアップ / 診断・監視）は
両パネルに同じ内容があるため、**変更するときは両方を修正する**。

## 保存について

- 共有版：Artifact の共有データベース（`sites` コレクション）。
- ローカル版：`localStorage`（キー：`security-checklist:v2`）。端末・ブラウザ間では共有されない。
- ローカル版の記録を共有版に移すときは、ローカル版で「データを書き出す」→ 共有版で「データを読み込む」。
- ブラウザのデータを消去すると記録も消えるため、定期的に「データを書き出す」でバックアップする。
- 1サイト版（キー：`security-checklist:v1`）のデータがあれば、初回表示時に1件目のサイトとして自動で引き継ぐ。

## 公開時に差し替えるもの

- `og:url` / `og:image` の `https://example.com/...`
- 検索エンジンに載せる場合は `<meta name="robots" content="noindex">` を削除
