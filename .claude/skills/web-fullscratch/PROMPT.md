# コピペ用 指示文テンプレート

`web-fullscratch` Skill を使って制作を依頼するときの指示文です。
`【】` の部分を埋めて使ってください。埋められない項目は「未定」と書けば、
確認すべき事項として扱われます。

---

## A. 新規サイトを1から作るとき

```
web-fullscratch のルールでフルスクラッチのホームページを作成してください。

# サイト概要
・サイト名：【株式会社◯◯】
・業種／事業内容：【　】
・ターゲット：【　】
・サイトの目的：【問い合わせ獲得 / 採用応募 / 会社紹介】
・参考にしたいトーン：【誠実・落ち着いた / 先進的 / 温かみ】
・使いたい色（あれば）：【#000000】

# 規模
・ページ数：【1ページ（LP） / 5ページ / 10ページ以上】
・下層ページの追加予定：【あり / なし】
・納品後の更新者：【自分 / クライアント / なし】
→ 規模判定の結果と、素のCSSかSCSSかを最初に提示してください。

# 必要なページ
【TOP / 会社概要 / 事業内容 / 採用情報 / お問い合わせ】

# TOPページの構成
【ヒーロー / 事業紹介 / 選ばれる理由 / お客様の声 / お知らせ / CTA / フッター】

# フォーム
・設置するページ：【お問い合わせ】
・項目：【お名前 / 会社名 / メールアドレス / 電話番号 / お問い合わせ内容】
・送信先：【未定 / 外部フォームサービス / PHP】

# 公開環境
・公開URL：【未定】
・サブディレクトリ公開の予定：【なし】

# 前提
・CMSは使わない
・jQuery・外部ライブラリは使わない
・画像は仮ファイル名でよい（後で差し替える）
・原稿は仮テキストでよい。仮の箇所は TODO コメントを入れること

まずディレクトリ構成を提示し、その後 HTML → CSS → JavaScript の順に
省略なしで実装してください。
```

## B. 既存のフルスクラッチサイトに追加・修正するとき

```
web-fullscratch のルールで作業してください。

# 対象
・プロジェクト：【doyg-corporate-site】
・対象ファイル：【assets/css/project/_p-news.css】
・対象ページ：【index.html】

# 依頼内容
【お知らせセクションにカテゴリータブを追加したい】

# 条件
・既存のデザイントークン（_variables.css）の変数を使うこと
・既存のクラス命名規則に合わせること
・依頼箇所以外は変更しないこと
・共通パーツを変更する場合は、反映が必要なページを報告すること

実装前に既存ファイルを確認し、影響範囲を先に報告してください。
```

## C. 大規模サイト（SCSS構成）を立ち上げるとき

```
web-fullscratch のルールで、SCSS構成のフルスクラッチサイトを立ち上げてください。

・ページ数：【12ページ】／下層ページは今後も追加予定
・複数人で運用する
・Dart Sass（@use / @forward）で構成すること
・src/scss/ を編集対象とし、assets/css/style.css はビルド生成物とすること
・package.json に dev / build スクリプトを用意すること
・globals（変数・mixin・関数）と foundation（トークン・リセット）を分けること
・ブレークポイントは mixin にまとめ、モバイルファーストで書くこと

まず以下を提示してください。
1. ディレクトリ構成
2. globals（_variables.scss / _mixins.scss）
3. foundation（_tokens.scss）
4. package.json とビルド手順

承認後に、共通パーツ（header / footer / button）→ 各ページの順で実装してください。
```

## D. 1ページのLPだけ作るとき

```
web-fullscratch のルールで1ページのLPを作成してください。
規模が小さいので、CSSは1ファイルにまとめて構いません。

・目的：【◯◯の資料請求獲得】
・構成：【ファーストビュー / 課題提起 / 解決策 / 特徴3つ / 料金 / よくある質問 / フォーム】
・CTA：【資料請求フォームへの誘導。スマホでは追従CTAを設置】
・トーン：【信頼感重視、装飾控えめ】

・IntersectionObserver によるフェードインを入れること
・prefers-reduced-motion に対応すること
・フォームは required / type / placeholder / autocomplete を正しく設定すること
・コードは省略せず、コピペでそのまま動く状態で出力すること
```

## 補足：必ず伝えたほうがよい情報

指示文に含まれていないと、こちらから確認が必要になる項目です。

| 項目 | なぜ必要か |
|---|---|
| ページ数・今後の追加予定 | 素のCSSかSCSSかの判断が変わる |
| 公開URL / サブディレクトリか | パス設計（ルート相対 / 相対）が変わる |
| フォームの送信先 | 静的HTMLだけでは送信できないため |
| 更新者が誰か | 保守設計の粒度が変わる |
| 支給素材（画像・原稿）の有無 | 仮置きするかどうかが変わる |
| 対応ブラウザ | 使える CSS / JS 機能が変わる |
