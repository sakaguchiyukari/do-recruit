# はじめにお読みください

このテンプレートは、Viteという道具を使って、Web制作でよく使う作業を自動化したスターターです。iro code.が配布しています。

はじめてViteをさわる方でも迷わないように、「何ができるのか」「どこをさわっていいのか」「困ったときはどうするのか」を順番に説明します。ゆっくり読み進めてください。

---

## このテンプレートでできること

セットアップは最初の一度だけです。あとは次の3つが自動になります。

1. scssのコンパイル（Preprosがいらなくなります）
2. パーツを増やしたときの `@forward` の書き足し（自分で書かなくてよくなります）
3. 画像の圧縮とWebP変換（1枚ずつ手作業する必要がなくなります）

---

## 準備するもの — Node.jsとは

Node.jsは、JavaScriptをパソコンの中で動かすための土台です。ふだんJavaScriptはブラウザの中で動きますが、このテンプレートで使うViteはブラウザの外（パソコン側）で動きます。それを支えているのがNode.jsです。

Node.jsが入っていないとViteは動きません。まずはこれを入れるところからスタートします。すでに入っているかどうか分からないときは、講座で確認方法をお伝えします。

---

## Viteとは

Viteは、コーディングを助けてくれる道具です。大きく2つの働きがあります。

- **開発サーバー**：ファイルを保存した瞬間に、ブラウザへ反映してくれます。
- **ビルド**：書いたコードを本番用に整えて書き出します（scssをCSSに変換したり、画像を軽くしたり）。

これまでPreprosでscssを変換していた作業も、画像を1枚ずつ圧縮していた作業も、Viteがまとめて自動でやってくれます。

---

## AIに手伝ってもらうときは

このテンプレートには、iro code.のコーディングルールが入っています。

```
AGENTS.md      AIへの指示書（どのAIもまずこれを読みます）
CLAUDE.md      Claude Code用の橋渡し
rules/         HTML・Sass・JavaScript・画像のルール
```

**Claude Code でも Codex でも、このフォルダを開いて話しかけるだけ**で、ルールに沿ったコードを書いてくれます。「ルールを読んで」と毎回お願いする必要はありません。

たとえば「ボタンのパーツを作って」と頼むと、`sass/module/` にファイルを作り、BEMで書き、色は変数を使い、余白は `margin-top` で……というところまで、ルール通りにやってくれます。

自分でコードを書くときも、`rules/` の中身がそのまま教科書になります。

## 使い方（3つのコマンド）

VS Codeでこのフォルダを開いて、ターミナルで次のコマンドを打ちます。

| コマンド | いつ使うか | 何が起きるか |
|---|---|---|
| `npm install` | 最初の一度だけ | 必要な部品をそろえます |
| `npm run dev` | 制作中ずっと | 開発サーバーが立ち上がり、保存するたびに画面へ反映されます |
| `npm run build` | 完成したとき | 本番用のファイルを `dist/` フォルダに書き出します |

`npm run dev` を実行すると、`http://localhost:5173` のようなURLが表示されます。それをブラウザで開いてください。止めるときは、ターミナルで `Ctrl + C` を押します。

VS Codeのサイドバーにある「NPM スクリプト」から、`dev` や `build` の横の再生ボタンをクリックしても同じことができます（このテンプレートには設定済みです）。

## どこをさわっていい？どこはさわらない？

はじめのうちは「どこを触ったら壊れるのか」が不安だと思います。次の表を目安にしてください。

| 場所 | 役割 | 扱い方 |
|---|---|---|
| `index.html` | サイトの中身 | **編集します** |
| `sass/module/` | パーツごとのCSS | **編集・追加します** |
| `sass/global/_variables.scss` | 色・幅・余白の設定 | **ここを変えてカスタマイズします** |
| `sass/base/` | リセット・土台 | 基本はそのままにします |
| `sass/global/_function.scss`・`_mixins.scss` | 便利な機能 | 基本はそのままにします |
| `sass/module/_index.scss` | パーツの目次 | **さわりません**（自動で作られます） |
| `vite.config.js` | 自動化の設定 | 基本さわりません（ページを増やすときだけ、決まった1行を追記します。「ページを増やす」参照） |
| `scripts/` | 自動化スクリプト | さわりません |
| `package.json` | コマンドの設定 | さわりません |
| `dist/` | 書き出した結果 | さわりません（納品はこの中身を渡します） |
| `node_modules/` | 部品置き場 | さわりません・人に渡しません |

## カスタマイズしてみよう

### 色を変える

`sass/global/_variables.scss` を開くと、色の設定があります。ここを書き換えると、サイト全体の色が変わります。

```scss
$color-accent: #3d7a8a; // メインの色
$color-text: #333;      // 文字の色
```

### インナー幅や余白を変える

同じ `_variables.scss` の中に、コンテンツの幅や余白の設定があります。デザインに合わせて数字を書き換えてください。

```scss
$inner: 1080px;     // コンテンツの横幅
$padding-sp: 20px;  // スマホのときの左右の余白
```

### パーツを追加する

`sass/module/` に `_パーツ名.scss` を作ります。ファイルの先頭に `@use "../global" as *;` と書けば、変数やmixinが使えます。

```scss
@use "../global" as *;

.card {
  padding: to-rem(24);
  background-color: $color-white;
}
```

保存すると、`module/_index.scss` に `@forward "card";` が自動で入り、スタイルが効きます。目次を自分で書く必要はありません。

### 画像を入れる

1. `images/` に画像（jpg・png）を置きます
2. 保存すると、同じ名前の `.webp` が自動でできます
3. HTMLでは `<picture>` を使い、WebPを優先して読み込みます

```html
<picture>
  <source srcset="./images/sample.webp" type="image/webp">
  <img src="./images/sample.jpg" alt="説明文" width="1080" height="608" loading="lazy">
</picture>
```

### ページを増やす

下層ページは `ページ名/index.html` の形で作ります（例: `about/index.html`）。

作ったら `vite.config.js` を開いて、`input` のところに1行追記します。追記する場所には、コメントで見本が書いてあります。

```js
input: {
  main: path.resolve(__dirname, 'index.html'),
  // ページを追加する場合はここに追記する
  about: path.resolve(__dirname, 'about/index.html'),
},
```

`vite.config.js` を触るのはこの1行だけです。ほかの部分はそのままにしてください。

## JavaScriptについて

JSは `js/script.js` に書きます。読み込みの設定は `index.html` の `<head>` 内に済んでいます。

```html
<script type="module" src="./js/script.js" defer></script>
```

講座で習った書き方との違いは、`type="module"` が付いていることだけです。これはViteを使うときの決まりで、この印が付いたJSだけをViteが変換してまとめてくれます。`type="module"` には `defer` と同じ「HTMLを読み終わってから実行する」働きが最初から入っているので、動き方は講座で習ったdefer付きのscriptと同じです。

JSファイルを増やすときも、同じ形で `<head>` に追加します。

```html
<script type="module" src="./js/hamburger.js" defer></script>
```

**大事な注意が1つあります。** `type="module"` のJSは、index.htmlをダブルクリックでブラウザに開くと動きません。ブラウザの安全機能で止められるうえ、見た目のエラーも出ないので「JSだけ効かない」ように見えます。表示の確認は必ず `npm run dev` で行ってください。`npm run build` のあとに `dist/` の中身を確認したいときも、ダブルクリックではなく `npm run preview` を使ってください。

## 自分で使うときの注意点

- **`module/_index.scss` は自分で編集しません。** 自動で作られるファイルなので、手で書き換えても次の保存で上書きされます。
- **新しいパーツの先頭には `@use "../global" as *;` を書きます。** これを忘れると、変数やmixinが使えずエラーになります。
- **画像は `images/` に置きます。** ほかの場所に置くと、WebPが自動で作られません。
- **人に納品・共有するのは `dist/` の中身です。** `sass/` や `node_modules/` は渡しません。
- **`node_modules/` は容量が大きいので、共有やアップロードには含めません。** `npm install` を実行すれば、いつでも作り直せます。

---

## 書き出した中身（dist）

`npm run build` を実行すると、`dist/` にこの形で書き出されます。ファイル名は書く前のまま（余計な英数字は付きません）。

```
dist/
├ index.html
├ css/styles.css       sass/styles.scss から作られたCSS
├ js/main.bundle.js    JavaScript
└ images/              画像（images/ のフォルダ構成のまま）
```

納品・アップロードは、この `dist/` の中身をそのまま渡します。

## 困ったとき

**JSが効かない**
index.htmlをダブルクリックで直接開いていないかを確認してください。このテンプレートのJSは `npm run dev` の画面でないと動きません（理由は「JavaScriptについて」の章にあります）。`npm run build` した `dist/` の確認は `npm run preview` を使います。

**スタイルが効かない**
パーツの先頭に `@use "../global" as *;` を書いたか、クラス名が合っているかを確認してください。開発サーバーを一度止めて、`npm run dev` で立ち上げ直すと直ることもあります。

**`npm run dev` でエラーが出る**
先に `npm install` を実行したかを確認してください。最初の一度をとばすと動きません。

**「Port 5173 is in use」と表示される**
すでに別の番号（5174など）で自動的に開いています。問題ありません。表示されたURLをブラウザで開いてください。

## WordPressで使うときは

このテンプレートは静的サイト用ですが、**Sassの書き方と自動化は、WordPressでもそのまま使えます**。

違うのはViteの役割だけです。静的サイトではViteがページそのものを作りますが、WordPressでは**ページはPHP（テーマ）が作り、ViteはCSS・JSを用意する裏方**に回ります。

実際のWordPress案件では、iro code.のWordPressテーマテンプレート（講座「Docker + WP-envで作ろう 新規制作編」で配布しています）を使ってください。この仕組みが最初から入っています。
