# 会議日程調整ツール (Meeting Scheduler)

「調整さん」型の会議・打ち合わせ日程調整ツールです。**ブラウザだけで使えます**。
WordPressなどへのインストールは不要で、`index.php` 1ファイルをサーバーに置くだけで動きます。

## 特徴

- **ブラウザだけで完結** — アプリのインストール・アカウント登録・ログインは一切不要。URLを開くだけ
- **誰でも・何度でも使える** — 調整は何件でも作成可能。決定の取り消し・候補の追加もできる
- **調整同士が干渉しない** — 調整1件ごとに専用のランダムURL（24文字トークン）を発行
  - 誰かが調整中でも、別の社員が新しい調整を同時に作成できる（お互いにブロックしない）
  - URLを知らない調整は一切見えない（公開の一覧ページは存在しない）
  - データもファイル単位で完全に分離（調整1件 = 1ファイル）
- **幹事用URLと参加者用URLを分離** — 日程の決定・削除などの管理操作は幹事しかできない
- **同時回答に強い** — 排他ロック付きで保存するため、複数人が同時に送信しても回答が消えない
- **大人数対応** — 30人以上でも横スクロール＋固定列の集計表で見やすく表示。
  ○△×の自動集計と「最も都合の良い候補」のハイライト付き
- **スマホ対応** — レスポンシブデザイン

## 設置方法（1回だけ）

**動作要件: PHP 7.4以上のWebサーバー**（レンタルサーバーでOK。データベース不要）

1. `meeting-scheduler` フォルダごとサーバーにアップロードする
   - 例: `https://example.com/schedule/` に置く場合は `schedule/index.php` となるように
2. ブラウザで `https://example.com/schedule/` を開く
3. 作成フォームが表示されれば完了。このURLを社内に周知すれば、誰でも使えます

初回アクセス時に同じ場所へ `data/` フォルダ（回答データの保存先）が自動作成されます。
フォルダに書き込み権限がない場合はエラーメッセージが表示されるので、
パーミッションを `755`（または `775`）にしてください。

## 使い方

### 幹事（調整を立ち上げる人）

1. トップページで会議名・候補日程（1行1候補）を入力して「作成」
2. 発行された2つのURLを控える
   - **参加者用URL** … メールやチャットで参加者全員に共有
   - **幹事用URL** … 自分だけが使う管理用URL（ブックマーク推奨。紛失すると幹事操作不可）
3. 回答が集まったら幹事用URLを開き、「この日程に決定する」で確定
   - 確定すると回答は締め切られ、全員のページに決定日程が表示されます

### 参加者

1. 共有されたURLをブラウザで開く
2. 名前を入力し、各候補に ○ / △ / × を選んで送信
3. 予定が変わったら、集計表の自分の名前の下の「編集」から回答を修正

### 幹事ができるその他の操作（幹事用URLのみ）

- 決定の取り消し（再募集）
- 候補日程の追加（既存の回答はそのまま維持されます）
- メモ（会議室・ZoomのURL・議題など）の更新
- 特定の回答の削除
- 調整そのものの削除

## 設定の変更

`index.php` 冒頭の定数で変更できます。

| 定数 | 既定値 | 内容 |
|---|---|---|
| `MS_RETENTION_DAYS` | 180 | この日数更新がない調整を自動削除（0で無効） |
| `MS_RATE_LIMIT` | 20 | 同一IPが1時間に作成できる調整の上限 |
| `MS_MAX_SLOTS` | 100 | 候補日程の上限数 |
| `MS_DATA_DIR` | `./data` | データ保存先フォルダ |

## セキュリティと運用上の注意

- URLトークンを知っている人だけがアクセスできる「URLを知っている＝閲覧可」方式です。
  参加者用URLは社外の人に転送しないよう周知してください
- 幹事用URLは参加者に送らないでください（誤送信すると誰でも日程決定・削除ができてしまいます）
- 幹事キーはハッシュ化して保存されるため、万一データファイルが読まれても幹事URLは復元できません
- 回答の「編集」は誰でも可能です（調整さんと同じ方式）。社内利用を想定した簡易運用です
- スパム対策としてハニーポット＋CSRFトークン検証、同一IPからの作成は1時間20件までの制限があります
- 検索エンジンには載りません（noindex, nofollow）
- **Apache** では `data/` フォルダに自動生成される `.htaccess` で直接アクセスが遮断されます。
  **nginx** の場合は以下の設定を追加するか、`MS_DATA_DIR` をWeb公開範囲外に変更してください:

```nginx
location ~ /schedule/data/ { deny all; }
```
